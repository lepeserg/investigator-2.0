# Следователь · Ведение дела

Применяй [общую основу Investigator 2.0](../investigator-2-0/SKILL.md). Это восьмое специальное направление комплекта. Данные конкретного дела сохраняй только в его папке проекта.

## Команды и результаты

| Команда пользователя | Результат |
|---|---|
| «Веди это дело», «На чём остановились?», «Продолжи работу по делу» | Сводка источников, рабочих документов, плана, открытых вопросов и следующего шага; продолжение разрешённой задачи |
| «Сумма изменилась», «Что затронет изменение даты?» | Связанные документы и записи, буквальные совпадения, непроверенная часть поиска; предложения по правке |
| «Какие запросы без ответа?», «Проверь полноту ответов» | Подтверждение направления, поступившие ответы, охват каждого пункта и периода, отсутствующие приложения |
| «Покажи противоречия», «Что осталось проверить?» | Обе версии со ссылками на источники, способ проверки, результат и основание разрешения |
| «Что по срокам?» | Ближайшие 7 дней включительно от даты просмотра и все более ранние незавершённые сроки; отдельный перечень требующих проверки |
| «Проверь ссылки на тома и листы» | Диапазоны по описи и буквальные ссылки в проекте, затем содержательная сверка с первоисточниками |
| «Проверь навык после обновления» | Общая самопроверка и воспроизводимые обезличенные испытания; отдельное указание границ проверки |

По умолчанию **каждое выполнение команды этого направления завершается отдельным Word-отчётом** и кратким выводом в чате. Промежуточные вопросы не требуют пустых отчётов. Для нескольких операций одного поручения можно выдать один итоговый Word-отчёт, охватывающий все результаты. Программные команды также сохраняют собственные отчёты. Автоматические напоминания не создавать без отдельного поручения.

## Рабочий порядок

1. Найди существующую папку проекта и реестр `_ведение_дела/state.json`. Не создавай вторую карточку того же дела. Если есть прежний план или карточка, сопоставь их и перенеси только проверенные записи с указанием источников; исходные файлы сохрани.
2. При первом ведении прочти [формат записей и команды](references/register-and-commands.md). Для существующего реестра перечитай номер редакции, проверь доступность и контрольные суммы источников. Изменившийся источник требует повторной проверки связанных записей. Не принимай старую сводку за актуальное состояние дела.
3. Обновляй реестр через `case_manager.py apply`, фиксируя основание и текущий номер редакции. Значения и содержательные оценки устанавливай чтением первоисточников. Выбранный режим исправлений Word указывай только после выбора пользователя. Источник, место в нём и статус экземпляра обязательны там, где заявляется подтверждение.
4. Выполни нужную операцию. Правила источников, последствий изменений, запросов, противоречий и ссылок — [operations.md](references/operations.md). Для сроков отдельно прочти [deadlines.md](references/deadlines.md), проверь применимое право и исходные события. Программа выполняет заданную арифметику, не выбирает норму или продолжительность самостоятельно.
5. Сформируй отчёт, проверь выводы и [оформление Word](references/reports-and-checks.md). Подготовку файла отделяй от фактического подписания, направления, проведения и учёта. Незаполненный реестр не доказывает отсутствие событий в деле.

Не запускай ведение дела полностью для опечатки или отдельного запроса, если пользователь не поручал вести проект. Если реестр уже используется и разрешённая работа изменила его состояние, актуализируй затронутые записи и включи результат в отчёт. Реестр не подменяет процессуальные документы.

## Инструменты

Общий запуск: `run.py case_manager.py --project <папка проекта> --help`. Команды `init`, `apply`, `report`, `impact` работают локально. Настройки: Word, горизонт 7 дней. `report --mode all --as-of YYYY-MM-DD` создаёт сводный отчёт; дату передавай из текущего контекста пользователя. Для точного контроля почасового срока передавай время и часовой пояс применительно к делу, не угадывай его по месту компьютера.

Самопроверка: `run.py check_skill.py`, затем `run.py case_manager_checks.py --verbose`. Порядок и границы испытаний — [reports-and-checks.md](references/reports-and-checks.md). Не называй структурную проверку независимой оценкой качества расследования.
