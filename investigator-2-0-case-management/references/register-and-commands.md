# Реестр и команды

## Хранение и продолжение

Реестр расположен в `<проект>/_ведение_дела/state.json`; история — `history/revision-NNNNNN.json`; отдельные отчёты Word и их машинные результаты — `reports/`. Новые отчёты не перезаписывают прежние. Источники могут находиться вне проекта и только читаются. Относительные пути документов считаются от папки проекта. Предпочитай их для файлов внутри проекта.

Сохраняй обозначение проекта из поручения, не придумывай номер дела. `init` не сканирует корпус и не устанавливает факты. Если нужное дело или папка неоднозначны, уточни это у пользователя до создания реестра. Реестр является рабочим журналом, а не официальной учётной системой.

Каждая запись имеет устойчивый уникальный во всём реестре ID: например `D1`, `F1`, `T1`, `R1`, `C1`, `L1`, `Q1`. ID не меняют при редактировании. Удаление записей программой не предусмотрено: прежние состояния сохраняются в истории. Не очищай историю для устранения противоречия.

## Запуск

Команды выполняет помощник через локальный Python и общий `run.py`; пользователь даёт поручения обычным языком. Запускатель находится в корне распакованного комплекта: `run.py`. Папку проекта выбирай вне репозитория по `projects_root` в `config.local.json` или прямому указанию пользователя.

```text
run.py case_manager.py --project <проект> init --label <обозначение>
run.py case_manager.py --project <проект> apply --patch <файл операции.json>
run.py case_manager.py --project <проект> report --mode summary
run.py case_manager.py --project <проект> report --mode requests
run.py case_manager.py --project <проект> report --mode contradictions
run.py case_manager.py --project <проект> report --mode deadlines --as-of 2026-10-10 --horizon 7
run.py case_manager.py --project <проект> report --mode citations
run.py case_manager.py --project <проект> report --mode all --as-of 2026-10-10
run.py case_manager.py --project <проект> impact --fact F1 --old 100 --new 200
```

Даты и суммы выше условные. Для реального запуска подставляй сведения текущего поручения. `impact` не изменяет ни реестр, ни исходные документы. `report` проверяет доступность и неизменность зарегистрированных источников и создаёт новые файлы отчёта. Содержательную оценку выполняет помощник.

## Формат операции

`expected_revision` должен совпадать с текущей редакцией. `reason` объясняет изменение. `upsert` полностью заменяет перечисленные записи с тем же ID; поэтому перед изменением перечитай запись и сохрани её незатронутые поля. Не передавай содержимое всей старой карточки из памяти. Коллекции, которых нет в операции, не изменяются.

`acknowledge_documents` содержит только ID фактически просмотренных источников. Программа сохраняет их контрольные суммы. Это техническая фиксация версии, не автоматическое признание содержания верным. Подтвердить неизменность источника недостаточно для подтверждения старого вывода: связанную запись нужно отдельно перепроверить и обновить.

Пример первой операции в условном проекте; файл источника должен существовать:

```json
{
  "expected_revision": 0,
  "reason": "Прочитана условная выписка и отмечено место сведений",
  "upsert": {
    "documents": [{"id": "D1", "title": "Условная выписка", "path": "источники/выписка.docx", "status": "рабочая копия"}],
    "facts": [{"id": "F1", "text": "В условном документе указана сумма 100", "status": "сведения документа", "sources": [{"document_id": "D1", "locator": "таблица операций, строка 2"}]}],
    "tasks": [{"id": "T1", "title": "Проверить сумму", "preparation": "в работе", "document_ids": ["D1"], "next_step": "Сопоставить с первичным банковским документом"}]
  },
  "acknowledge_documents": ["D1"]
}
```

После успешной операции версия увеличивается на единицу; прежнее состояние сохраняется. Одновременная запись блокируется. После ошибки экспорта перечитай `state.json`: изменение могло сохраниться до отказа Word-отчёта. Блокировку `write.lock` не удаляй, пока не установлено, что другой процесс больше не пишет реестр.

## Коллекции и поля

| Коллекция | Поля записи |
|---|---|
| `documents` | `id`, `title`, `path`, `status`; при необходимости `fact_ids`, `revisions`, `revision_choice_source`, `volume`, `leaf_start`, `leaf_end`, `inventory_sources` |
| `facts` | `id`, `text`, `status`, `sources` |
| `tasks` | `id`, `title`, `preparation`, `document_ids`, `next_step`; необязательное подтверждённое событие `actual` |
| `requests` | `id`, `title`, `document_id`, `items`; необязательные `sent`, `responses`, `fact_ids` |
| `contradictions` | `id`, `title`, `status`, `versions`, `check_action`; для разрешённого — `resolution`; при необходимости `fact_ids` |
| `deadlines` | `id`, `title`, `event_on`, `sources`, `basis`, `calculation`; при необходимости `completed`, `superseded_by`, `supersession_sources`, `fact_ids` |
| `citations` | `id`, `document_id` проекта, `target_id` источника, `locator`, `literal`, `volume`, `leaf_start`, `leaf_end`; необязательная записанная оценка `content_review` |

Источник — объект `{"document_id":"D1","locator":"т. 1 л.д. 5, строка операции"}`. Если известна только страница PDF, так и записывай. Для сообщения пользователя сохрани локальную запись его сообщения с датой и пометь документ статусом `сообщение пользователя`; не называй её подписанным документом.

Статусы документов: `рабочая копия`, `подписанный документ`, `скан`, `сообщение пользователя`, `образец`, `не установлен`. Статусы фактов: `сведения документа`, `показания`, `подтверждено`, `версия`, `правовой вывод`, `неизвестно`, `противоречие`. Подтверждение выбирается по содержательной оценке, не по числу повторений.

Статусы подготовки: `не начато`, `в работе`, `проект с пробелами`, `проект после проверки`. Событие `actual`, `sent` или `completed` задаётся объектом с `status`, `date` в ISO-формате и непустым `sources`. Название события конкретное: например «направлено» или «проведено». Без подтверждения поле отсутствует.

Контрольные поля `sha256`, `reviewed_at`, `_source_hashes`, номер редакции и история назначаются программой. Не редактируй их вручную, не подставляй их в `upsert`. Значения контрольных сумм в реестре не являются экспертным заключением о подлинности файла.
