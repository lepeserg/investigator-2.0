# Сроки с объяснением расчёта

## Правило работы

Программа не содержит универсального набора процессуальных продолжительностей и не назначает срок по названию документа. Перед расчётом установи исходное событие, дату/время, применимую норму и редакцию, специальные исключения, решения об изменении срока и их последствия. Используй [общий порядок сверки права](../../investigator-2-0/references/14-plenums-and-search.md) и профиль `decisions`. Запросы в сеть — только о нормах, без данных дела.

Отделяй установленную законом продолжительность, срок конкретного решения и желаемую дату внутреннего плана. Не подставляй срок ответа из пользовательского шаблона как универсальную норму. Флаг `reviewed` означает записанный результат проверки помощником, а не автоматическую проверку закона программой.

## Поля

- `event_on`: ISO-дата исходного события либо ISO-время с часовым поясом для почасового расчёта.
- `sources`: документ и точное место, подтверждающее исходное событие и существенные решения.
- `basis`: `reviewed: true`, `rule` — текст применённого правила, `source` — ссылка/реквизиты правового источника, `checked_on` — дата сверки, `applicability` — почему это правило применимо к данному событию. Если это дата внутреннего плана, прямо укажи это, не называй её процессуальным сроком.
- `calculation`: явный способ арифметики. При неполных данных запись сохраняется, но расчёт попадает в раздел «Требует проверки».

Поддержаны четыре способа:

| `kind` | Поля и поведение |
|---|---|
| `date` | `due_on`: дата непосредственно из проверенного решения/источника |
| `days` | `amount`: положительное число календарных дней; `include_start`: явно true/false |
| `months` | `amount`: положительное число календарных месяцев; `month_overflow`: `last_day` либо `error` при отсутствии соответствующего числа |
| `hours` | `amount`: положительное число часов; исходное время обязательно с часовым поясом; автоматический перенос не поддержан |

Для всех способов явно задаётся `roll`: `none` либо `next_workday`. Второй режим требует `calendar` с `source`, `checked_on`, `start`, `end`, `nonworking_dates`. Список нерабочих дат должен быть полным для заданного интервала, включая обычные выходные и применимые переносы; программа не считает субботу/воскресенье автоматически нерабочими. За границами проверенного календаря расчёт останавливается. Правомерность переноса устанавливается до его применения.

При изменениях, приостановлениях, зачётах, объединении сроков или специальном порядке не моделируй их произвольным сложением. Сделай содержательный расчёт по проверенной норме и решениям, затем зарегистрируй подтверждённую итоговую дату способом `date` с полным объяснением. Прежнюю запись пометь `superseded_by` и приложи `supersession_sources`. Завершение отражается в `completed` только с источником.

## Условный арифметический пример

Это испытательный пример, он не устанавливает законный срок для какого-либо действия:

```json
{
  "id": "L1", "title": "Условный срок для испытания", "event_on": "2026-10-01",
  "sources": [{"document_id": "D1", "locator": "дата условного события"}],
  "basis": {"reviewed": true, "rule": "Условное правило пять календарных дней без начального дня", "source": "Синтетический пример, не норма права", "checked_on": "2026-10-10", "applicability": "Только проверка арифметики"},
  "calculation": {"kind": "days", "amount": 5, "include_start": false, "roll": "none"}
}
```

## Выдача

По умолчанию показывай ближайшие 7 дней и все просроченные незавершённые записи, независимо от давности. `--as-of` передаётся явно из текущего контекста. Дата просмотра и крайняя дата включены. Для точного почасового статуса нужно текущее время и релевантный часовой пояс; при одной дате не объявляй сегодняшнее почасовое событие просроченным.

Изменённые/недоступные источники и непроверенные основания выводятся отдельно, а не исчезают из календаря. Для каждого рассчитанного срока показывай исходное событие, арифметику, итог, основание и дату сверки. Формулировка «просрочен по зарегистрированным данным» требует проверки полноты сведений о выполнении. Не утверждай нарушение закона только по записи календаря. Напоминания по расписанию этим навыком сами не создаются.
