# Проверка состояния дела

## Продолжение работы

Прочти реестр и текущий план, проверь зарегистрированные файлы. Если источник изменился, найди связанные факты, задачи, запросы, сроки, противоречия и ссылки; оцени, какие выводы затронуты. Программа сохраняет версию источника для каждой записи: повторная фиксация источника сама по себе не обновляет все выводы. Недоступность файла указывай как ограничение, не как отсутствие документа в деле.

Укажи рабочие версии по фактическим решениям и сведениям пользователя; дата изменения файла не устанавливает актуальность обвинения или подписания. Если в Word есть непринятые исправления, следуй общему порядку выбора редакции. Уже проведённое действие не объявляй непроведённым только потому, что подтверждение не зарегистрировано.

## Последствия изменения

Установи ID обстоятельства, прежнее и новое значения и источник уточнения. Запусти `impact`; он ищет зарегистрированные связи и буквальные совпадения в зарегистрированных DOCX, текстовых файлах и PDF с текстовым слоем. Старые DOC, сканы без текста и непрочитанные файлы остаются в перечне ограничений. При необходимости локально подготовь читаемые копии и зарегистрируй их связь с оригиналом.

Буквальный поиск не устанавливает семантическую связь и может не найти число, записанное словами или в другом формате. Просмотри контекст каждого кандидата и связанные записи. Результат: **документ/место → прежнее значение → новый источник → предполагаемое изменение → статус экземпляра**. Никаких массовых замен на основании одного совпавшего числа. Подписанные и процессуально вынесенные документы не переписываются как черновики.

## Запросы и ответы

Для каждого запроса фиксируй предмет по пунктам. `sent` заполняй лишь по подтверждению направления. Дата документа и файловая дата этого не подтверждают. В `responses` регистрируй источник ответа, дату получения и приложения.

```json
{
  "id": "R1", "title": "Условный запрос операций", "document_id": "D2",
  "items": [{"id": "1", "question": "Операции за январь — март", "period": ["2026-01-01", "2026-03-31"], "covered_period": ["2026-02-01", "2026-03-31"], "assessment": "частичный", "assessment_note": "Сведений за январь нет", "sources": [{"document_id": "D1", "locator": "период выписки"}]}],
  "responses": [{"document_id": "D1", "received_on": "2026-10-09", "attachments": [{"title": "Указанное в письме приложение без представленного файла"}]}]
}
```

Оценки пункта: `полный`, `частичный`, `не отвечает`; отсутствие оценки означает «не оценено». Оценку даёт помощник после чтения, указывая объяснение и источники. Периоды — две ISO-даты включительно. При нескольких раздельных интервалах не скрывай разрыв общей рамкой: раздели пункты или объясни пробел в оценке. Приложение связано с `document_id`; если файл не представлен, ID не указывай. Ответ с реквизитами счёта не отмечай полным ответом на запрос операций. Направление повторного письма требует отдельного поручения; проект готовится через `correspondence`.

## Противоречия

Для одного расхождения сохраняй устойчивый ID, две или более версии и источники каждой. Статусы: `открыто`, `проверяется`, `разрешено`. В `check_action` указывай конкретную проверку. Статус `разрешено` требует `resolution` с текстом, датой и источниками; обе исходные версии сохраняются.

```json
{
  "id": "C1", "title": "Разные суммы", "status": "проверяется",
  "versions": [
    {"text": "В первом источнике 100", "sources": [{"document_id": "D1", "locator": "строка 2"}]},
    {"text": "Во втором источнике 200", "sources": [{"document_id": "D2", "locator": "абзац 3"}]}
  ],
  "check_action": "Сверить первичный документ и назначение каждой суммы"
}
```

Изменение источника делает прежний результат разрешения требующим проверки. Совпадение значения после редактирования проекта само по себе не разрешает доказательственное противоречие. Содержательный разбор веди через `analysis`.

## Том и листы дела

1. По описи зарегистрируй документ и его диапазон `volume`, `leaf_start`, `leaf_end`; укажи опись через `inventory_sources`. Сплошной диапазон применяй только к действительно непрерывному документу. Нестандартные листы с буквами и разрозненные диапазоны не преобразуй в целые числа: проверяй вручную и явно указывай ограничение.
2. Из текущей выбранной редакции проекта извлеки ссылки. На каждую создай запись `citations`: проект, точное место, буквальный текст, ожидаемый документ-источник, том и границы. Для нескольких документов в одной ссылке создавай отдельные записи.
3. Программой проверь диапазон, присутствие буквального текста и свежесть источников. Поиск незарегистрированных ссылок является вспомогательным и распознаёт только распространённую запись «т. … л.д. …»; полный перечень сверяет помощник.
4. Открой соответствующие страницы/листы и проверь, что там действительно содержится нужный документ и утверждение. Запиши содержательную оценку и её источник; программа не делает её за тебя.

Совпадение границ по описи не подтверждает содержание. Программа не угадывает соответствие PDF-страниц листам дела и не выполняет автоматический OCR. Для недоступных сканов вывод — «не проверено по первоисточнику». При подготовке ОЗ продолжает действовать итоговый контроль направления `charging`.
