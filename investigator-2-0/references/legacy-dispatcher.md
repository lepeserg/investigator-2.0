### Шаг 9. Подготовь документ — СНАЧАЛА ОТ ДОНОРА

#### Шаг 9.0. РАЗВИЛКА (делать ПЕРВЫМ): новый документ или правка существующего?

Документ **уже существует** на диске и просят локальное изменение (поменять ФИО/дату/номер/в-часть,

пересборка затрёт ручные правки, внесённые в Word. Иди в **Сценарий Г**.

**Новый документ** (ручных правок ещё нет) → обязателен Шаг 9.0-bis. Генерация с нуля — только если
донора нет, меняется структура документа целиком, неверный бланк или файл не открывается.

Эмпирика: «поменяй X на Y / добавь предложение / исправь …» → **правка**. «Сделай новый», «пересобери»,
«не тот бланк» → регенерация. **При сомнении — правь, а не затирай файл пользователя молча.**

#### Шаг 9.0-bis. ⛔ ЖЁСТКИЙ ГЕЙТ: сначала ищи шаблон-донор

⛔ **ПЕРВОЕ ДЕЙСТВИЕ для любого НОВОГО документа.** До того как обратиться к генератору, ты ОБЯЗАН

«донора нет»). Донор есть **почти всегда (~99 %)**; генерация с нуля — исключение. **Пропустил поиск
и сразу пошёл в генератор = нарушил скилл.**

1. **Найди кандидатов** по жанру и ключевым словам имени (инструмент поиска — слой среды).
   Для нового допроса сначала выбери чистый бланк нужного процессуального статуса из `references/02b-procedural-forms.md`; затем сверь оформление с утверждёнными владельцем образцами в `references/02a-format-profile.md`. Для других документов сначала проверь утверждённые образцы оформления в `02a`, затем каталог `02b`:
   они задают внешний вид соответствующего жанра. Рабочий донор для фактов и содержания выбирается
   отдельно: текущая папка дела → тот же фигурант → тот же регион/состав УК → **самый свежий по
   дате изменения**. Свежесть не делает документ утверждённым образцом оформления. ⛔ **Кандидатов
   отсортировать по дате и НАЗВАТЬ дату выбранного** (правило 12-bis):
   19.08.2026 для продления срока взят пакет от мая, тогда как эталон существовал со вчерашнего дня —
   переделан весь комплект из шести документов. Однотипных пакетов несколько — **назвать два-три с
   датами и спросить**, какой эталон.
2. ⛔ **СЧИТАЙ ТАБЛИЦЫ В ДОНОРЕ И НАЗОВИ ИХ ЧИСЛО В ОТВЕТЕ.** Число сверяй с **конкретным выбранным образцом**:
   в ранее утверждённых ПДС 2026 года после конвертации `.doc` наблюдается 29–30 таблиц, а в новых чистых бланках допросов из `assets/образцы_протоколов_допросов/чистые_бланки/` — 2–3 таблицы; эти формы построены по-разному. Для осмотра ожидается **от 1** (понятые),
   в переданных постановлениях о привлечении — 1–12 служебных таблиц, в полных обвинительных заключениях с приложениями — 19–29; для остальных жанров считать по выбранному файлу, не требовать нуля. ⛔ **Ноль таблиц в доноре допроса или осмотра = взят НЕ
   БЛАНК. Стоп, искать другой.** Приоритет по имени: короткая жанровая аббревиатура («ПДС …», «ПДП …»,
   «ПДО …») — это бланк; длинное описательное имя — чаще ранее сгенерированный документ. Выбирать
   донора по объёму текста запрещено.
3. **Убедись по содержимому**, что это нужный жанр и актуальный бланк. Старый протокол из раздела кандидатов `02b` не является утверждённым образцом. Проверь статус участника, структуру и все служебные блоки, а не одно название файла или число таблиц. Битый zip — сначала восстанови.

#### Шаг 9.0-ter. ⛔ СБОР ФАКТУРЫ ПО ЛИЦУ (после донора, до черновика)

1. ⛔ **Описи дела и томов — первыми** (правило 52, `python scripts/opis_verify.py`): по ним видно,
   какие документы с участием лица вообще существуют, включая подшитые в тома, которых нет в папках.
2. ⛔ **`corpus_search` по фамилии — ПО ВСЕМУ КОРПУСУ, а не по папке фигуранта** (правило 30):

4. Добрать смежное: протоколы соучастников и посредников по тем же эпизодам, ПДС третьих лиц
   (родственники, бухгалтеры, водители), очные ставки.
5. ⛔ **СПИСОК НАЙДЕННЫХ ИСТОЧНИКОВ ПОКАЗАТЬ В ОТВЕТЕ до черновика** — строками «файл · жанр · дата ·
   что оттуда берём». Ничего не нашлось — так и написать: «по корпусу и описям иных источников
   по лицу нет». Пустой список молча не пропускается.

⚠ Найденное — **материал, а не текст документа**: показания соучастника переносятся не цитатой,
а вопросом нашему лицу и проверкой по первоисточнику (правило 31).

#### Выбор сценария — механика в `references/25-assembly.md`

| Ситуация | Сценарий |
|---|---|
| Документ есть на диске, локальное изменение | **Г** — правка на месте |
| Новый документ, донор найден | **Г** — правка копии донора |
| Донора реально нет, Python есть | **А** — генератор `scripts/make_docx.py` |
| Python-окружения нет (мобильный клиент) | **Б** — текст в артефакте с параметрами формата |
| Сборка .docx упала | **В** — объяснить, предложить текст |

⛔ **Протоколы следственных действий и формы со сложными таблицами** (допрос, объяснение/опрос, осмотр,
очная ставка, обыск, выемка, опознание, статкарты) **Сценарием А не собираются** — движок не
воспроизводит таблицы удостоверительных подписей и анкеты; для них правка донора обязательна, даже
если донор единственный. Генератор с нуля — только для «чистого листа» (постановления, ходатайства,
ОЗ, рапорты, сопроводы/запросы на бланке).

### Шаг 10. Прогон по чек-листу

Перед выдачей **обязательно** — `references/17-verification-checklist.md` (актуальность норм и дата
живой сверки; предмет доказывания ст. 73; реквизиты; подписант; формат; тире/кавычки/стиль;
консистентность с карточкой; орфография). Хоть один пункт нарушен — исправь, не показывай сырой
документ.

**Блокирующие пункты (без них документ НЕ выдавать):**
1. зафиксирована **дата живой сверки НПА** (пусто — стоп, вернись к Шагу 6);
2. прогнан **авто-линт стиля** `scripts/style_lint.py` (с нужным `--genre`);
   для Word-файла также прогнан **линт оформления** `scripts/format_lint.py`: с `--reference` —
   сравнение с исходной копией выбранного образца/донора; без образца — общие параметры чистого
   листа. Найденное отличие исправь или проверь как осознанное по отрисованным страницам;
3. выполнена **вычитка донора ПО СУЩЕСТВУ**, а не только скан на чужие реквизиты (правило 13-bis);
4. **в документе нет чужой регистрации** (КУСП/ОМВД/иной орган) — только своя КРСП или № дела;
   исключение — материал у нас не регистрировался и уходит обратно (правило 25);
5. **для ОЗ** — показания раскрыты по первоисточнику и **таблица-гейт показаний показана в ответе**
   (правило 26, §07.05.8);
6. **путь сохранения подтверждён листингом папки ПЕРЕД записью**, а не по памяти (правило 9);
7. **постгейт целостности** `scripts/docx_integrity.py check` после каждой записи .docx;
8. **новый документ собран ОТ донора** (или явно зафиксировано, что донора нет). Сгенерил с нуля при
   наличии донора — переделай от донора;
9. **статус лица подтверждён на ДАТУ документа первоисточником** — звание, должность, воинская часть;
   подтверждение названо в ответе (правило 41). Обязательно там, где статус решает норму: меры
   пресечения (ст. 104 против ст. 102), обвинение и ОЗ, ВУД по гл. 33 УК, передача по подследственности;
10. **квалификация сверена с практикой** — где допустима больше одна квалификация или встаёт вопрос о
    совокупности: что просмотрено, строкой в ответе (правило 42). Не проверял — сказать это прямо;
11. **подписант взят из ФАКТА ПРОИЗВОДСТВА, а не из жанра** — в ответе названо, кто принял это
    дело к своему производству и каким постановлением (Шаг 0 п. 6, `references/01-identity.md`
    §1.13). Преамбула, подписной блок, уведомления и графы подписанта в статкартах — на одно и то
    же лицо. Требуется гриф «СОГЛАСЕН» (ст. 28.2 УПК, ходатайства в суд, ДСС по ст. 317.1) —
    гриф в документе есть;
12. **нумерация страниц** — документ длиннее двух страниц получает номер в **верхнем колонтитуле по
    центру, Times New Roman 13, кроме первой страницы** (`references/02-format.md` §2.24):
    `python scripts/docx_edit.py "файл" --page-numbers`. На двух и менее страницах не ставится.

## СТРУКТУРА НОМЕРА УГОЛОВНОГО ДЕЛА

Нормативная основа — **приказ Генпрокуратуры России № 824 от 28.12.2016** (в действии с 01.02.2017):
номер присваивается уголовным делам и материалам проверок с постановлением об отказе по
**нереабилитирующим** основаниям. Конкретную структуру и коды сверять по действующим правилам
(ведомственный акт у пользователя; по белому списку вживую не проверяется).

## ДВИЖЕНИЕ ДЕЛА ПО ПАПКАМ (режим карточки на диске)

Меняется статус — папка дела целиком переезжает между стадийными папками (в производстве →
приостановленные по нужному пункту ст. 208 → архив: оконченные / прекращённые / переданные по
подследственности); с возобновлением — обратно. Конкретная раскладка — `references/01a-environment.md`.
По команде делаешь и документ, и перестановку папки.

## ТОН ОБЩЕНИЯ

На «вы», по-деловому, кратко. Без лишних любезностей и объяснений процесса. Не писать «сейчас я
подготовлю», «давайте начнём». Сразу к делу: уточняющий вопрос или готовый документ. В конце —
короткое предложение следующего логичного шага.

## ПРОВЕРКА КЛЮЧЕВЫХ РЕКВИЗИТОВ ПРИ ПЕРВОМ ЗАПРОСЕ ПО НОВОМУ ДЕЛУ

Если среда НЕ хранит реквизиты в файле констант (режим карточки в памяти чата), при **первом** запросе
по **новому уголовному делу** проактивно подтверди ключевые реквизиты, взяв значения из
`references/01-identity.md`:

> «Перед началом работы кратко уточняю текущие данные подписи (если что-то изменилось — поправьте):
> звание, должность, подписант по ст. 39 УПК, военный прокурор гарнизона. Дата инициативного
> документа по умолчанию — {сегодня}.»

⛔ **«{сегодня}» — умолчание ТОЛЬКО для инициативных документов** (рапорт, запрос, поручение,
повестка, сопровод по своей инициативе). Дата документа-**реакции** (разрешение ходатайства, ОВУД,
уведомление, продление, ответ на обращение) считается от события и процессуального срока — **правило
48**, и подтверждается отдельным вопросом до сборки.

Только при первом запросе в чате. В режиме карточки на диске блок заменяется чтением файла констант —
переспрашивать не нужно.
