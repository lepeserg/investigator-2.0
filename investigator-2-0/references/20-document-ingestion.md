# 20. Приём входящих сканов, фото и PDF (распознавание и опись)

> Публичная редакция: частные примеры и локальные реквизиты исключены. Применяй основной SKILL.md и 27-case-workflow.md; прежние отметки «сверено», количественные ориентиры и настройки среды не подтверждают актуальность права или готовность текущего документа. Бланки подключаются локально.

Этот файл описывает, как принять и прочитать приложенные материалы (фото документов, сканы дела, «материалы проверки», объяснения, постановления, банковские выписки), в том числе **рукописные**, и составить по ним опись. Выполняется на **Шаге 0**, до классификации жанра.

## Рабочее окружение Investigator 2.0 (06.10.2026)

Использовать локальное окружение через `python ../run.py <скрипт> ...`. Проверка: `python ../run.py check_env.py`. Установлены PyMuPDF, python-docx, pypdf, Pillow, OCRmyPDF 17.13, Tesseract с русским языком, pypdfium2. Простой PDF с текстовым слоем создаётся без Ghostscript; PDF/A отдельно не проверен. Marker/Surya не установлен, рабочий OCR – Tesseract. Файлы не загружать в сторонние сервисы. Для Word и старых DOC доступен Microsoft Word через отдельный экземпляр COM.

Исходные материалы сохранять неизменными. Перед командами, создающими рядом с входом служебные файлы, делать рабочую копию в папке проекта. Результаты OCR, изображения и исправленные документы сохранять в проекте. Проверенные версии – в `../runtime/requirements-lock.txt`.

## Чтение Word и результат OCR

`scripts/extract_docx.py` сохраняет порядок абзацев и таблиц. Общий модуль `scripts/word_text.py` используется также поиском `scripts/corpus_search.py`. По указанию пользователя от 08.10.2026 при непринятых исправлениях Word содержательное чтение останавливается: уточни, какую редакцию использовать. Не выбирай автоматически. После ответа пользователя `--revisions current|original|marked` задаёт представление для чтения (marked — сравнение обеих версий с метками), не принимает исправления и не устанавливает согласование. Поиск с такими непрочитанными файлами сообщает неполноту и не подтверждает отсутствие сведений. Изображения и подписи проверяй визуально в оригинале.

Ошибка движка `scripts/ocr_smart.py` даёт неуспешный код и сообщение о файле/странице; частичное распознавание не выдаётся как полный результат. Пустой текст при успешной работе движка сам по себе не подтверждает пустоту страницы: применяй визуальную сверку по правилам ниже.

## Алгоритм (дерево решений)

1. **Фото (JPG/PNG/HEIC) или одиночное изображение** → читай напрямую инструментом просмотра. OCR-движок отдельно обычно не нужен: зрение модели хорошо разбирает русский рукописный текст.
2. **PDF** → сначала узнай структуру:
   ```
   python ../run.py pdf_ingest.py info "<путь к PDF>"
   ```
   В ответе: число страниц, есть ли текстовый слой, скан это или нет, примерный dpi, размер, и поле `recommendation`.
3. **`recommendation: render+read`** (скан без текста, либо файл >100 МБ, либо >20 страниц – встроенный просмотр не откроет такой PDF):
   ```
   python ../run.py pdf_ingest.py render "<путь>" <начало> <конец> 200
   ```
   Скрипт сложит страницы в JPEG (≈200 dpi) в папку `_render` рядом с PDF и напечатает пути – открой эти JPEG и читай. Бери разумными партиями (по 6–8 страниц).
**3-bis. Печатный текст скана – `ocr_smart` (на этом компьютере Tesseract).** Для ПЕЧАТНЫХ сканов, где важны точные строки (ФИО, № дела/КУСП, даты, суммы, латинские термины — напр. «PVP», «N-метилэфедрон»):
```
python ../run.py ocr_smart.py "<путь>" [начало] [конец]
```
Движок — **marker/surya на GPU** (`--force_ocr --disable_ocr_math`, без «математики»), при недоступности — **откат на Tesseract rus** (у кого marker не установлен); использованный движок помечен в шапке `[OCR: ...]`. Надёжнее визуального чтения для реквизитов. **Рукопись им НЕ распознавай** — для рукописного текста рендер + чтение зрением модели. marker — в отдельном окружении (env `MARKER_ENV`/`MARKER_SINGLE` или `…\marker-env`). Для больших сканов вызывай постранично.
4. **`recommendation: read_or_text`** (есть текстовый слой, файл небольшой) → читай PDF напрямую или достань текст:
   ```
   python ../run.py pdf_ingest.py text "<путь>" [начало] [конец]
   ```
5. **Нужен искомый (копируемый) экземпляр в дело** → добавь текстовый слой:
   ```
   python ../run.py pdf_ingest.py ocr "<вход.pdf>" "<выход_ocr.pdf>" rus
   ```
   Выходной PDF сохранять в папке проекта. Команда использует OCRmyPDF с `--output-type pdf`. Русский текст и поиск проверены на контрольном скане.
6. **Быстрый извлекатель для цифровых PDF** (если в окружении есть `система\текст.py` или аналог) – тянет текстовый слой напрямую без рендера (доли секунды на страницу); для сканов та же утилита уходит в OCR на всех ядрах. Это опциональная быстрая альтернатива шагам 3–4, а не замена им.

## Качество распознавания рукописного

- Оптимум для рукописи – рендер **200–300 dpi**; при плохом снимке подними dpi и попроси переснять ровно, без бликов.
- Классический Tesseract рукопись распознаёт плохо и годится только как запасной вариант. Основной путь для рукописного текста: отрендерить страницы в чёткие изображения 300 dpi (`pdf_ingest.py render` / `pdftoppm`) и прочитать их собственным зрением модели, а не полагаться на OCR-движок.
- **Рукописные ФИО, номера (КУСП, дела, г/н, телефоны), даты и суммы помечай как «прочтение – сверить с оригиналом».** Печатный текст читается уверенно, рукописный – нет. Не подставляй непроверенные рукописные данные в процессуальные документы.

## После прочтения – обязательно

2. **Занеси ключевые данные в карточку дела** (`17-verification-checklist.md`): фигурант, потерпевшие, статья, эпизоды, КУСП/КРСП, сроки, вещдоки.
3. **Зафиксируй расхождения** между документами (марки/госномера ТС, ФИО, суммы ущерба, число листов в сопроводе против фактического) и вынеси их пользователю отдельным списком «проверить».
4. Если из материала следует подследственность {ВСУ} (военнослужащий, передача по подследственности, вх. штамп {ОРГАН_СОКР}) – предложи следующий процессуальный шаг (рапорт ст. 143, продление проверки ст. 144 – см. `23-genres-144-proverka.md`, либо ВУД – см. `05-genres-lifecycle.md`).

## Извлечение анкеты из паспорта

- Первоисточник ФИО/ДР/паспортных данных – скан паспорта и ВУД, а НЕ анкета протокола допроса (в анкетах бывают опечатки в именах собственных). При расхождении написания имени собственного приоритет у паспорта/ВУД, анкету правим под них.
- Дату рождения СВЕРЯТЬ с машиночитаемой зоной (MRZ, YYMMDD): при нечётком скане визуальное поле читается неуверенно. Пример: визуально «16.02.1983», MRZ «830218» → верно 18.02.1983.
- Место рождения – как в паспорте (нас. пункт + район/область/республика, при необходимости с исторической формой «… АССР»).
- Регистрация: различать ТЕКУЩУЮ и снятую («снят с регистрационного учёта … г.»). В пакет запросов брать действующую.
- Семейное положение – из соответствующей страницы (брак/расторжение, дата, супруга).
- Рукописные и нечёткие ФИО, номера, даты – помечать «прочтение – сверить с оригиналом», в процессуальные документы без подтверждения не вносить.
- Национальность не предполагать – указывает следователь.

## Восстановление битых .docx

Файлы на смонтированной папке периодически открываются как «битый zip» (нет EOCD центральной директории – артефакт облачной синхронизации или блокировки Word):

1. Сначала проверь, не открыт ли файл в Word: рядом есть скрытый `~$<имя>.docx` – это блокировка, а не повреждение; попроси закрыть файл.
2. При чтении и записи на mount используй `safe_doc(path)` / `safe_save_copy(doc, dst)` из `make_docx.py` (копия в /tmp, проверка `zipfile.is_zipfile`, повтор N раз).
3. Если файл действительно обрезан – запусти `python ../run.py docx_recover.py "<битый.docx>"`: пересоберёт zip по локальным заголовкам (raw deflate) и сохранит `<имя>_recovered.docx`. Затем работай с восстановленным файлом.

## Где сохранять рендеры страниц PDF

Рендеры страниц PDF и сканов для просмотра сохраняй в папку, доступную инструменту чтения (`outputs/<папка дела>`), а НЕ в /tmp песочницы – иначе изображения не открываются.

## Конфиденциальность

Обрабатывай материалы уголовного дела **только локально**. Не отправляй сканы/фото во внешние OCR-облака (Яндекс, Google и т.п.) – это передача данных дела третьему лицу. Рендер (poppler/PyMuPDF) и OCR (Tesseract/marker) работают офлайн — и в песочнице, и на машине пользователя; наружу ничего не уходит.

## HEIC с iPhone — только pillow-heif, НЕ ffmpeg ★

iPhone пишет HEIC **тайлами 512x512**; ffmpeg их не собирает в целое изображение даже через
`-map 0:g:0` — три попытки в поле окончились ничем (боевой отчёт 05.08.2026).

**Правильно:** сразу поставить и использовать pillow-heif —

```bash
pip install pillow-heif
```
```python
import pillow_heif; pillow_heif.register_heif_opener()
from PIL import Image
Image.open(path).save(out_jpg, quality=92)   # дальше — обычный путь рендера/чтения
```

⛔ Не тратить попытки на ffmpeg/ImageMagick: это не вопрос ключей, а формат хранения тайлами.

## 20.91. ⛔ ГРАНИЦА ДОКУМЕНТА В СКАНЕ — ПО БЛАНКУ, А НЕ ПО РАСПОЗНАННОМУ ТЕКСТУ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

**Начало документа опознаётся по реквизитам БЛАНКА, видимым на рендере:**

| Признак | Где смотреть |
|---|---|
| герб / эмблема организации | верх листа |
| наименование организации, адрес, ИНН | угловой штамп либо шапка |
| поле «исх. № … от ДД.ММ.ГГГГ» и адресат | верхняя треть листа |
| подпись, должность, исполнитель | конец ПРЕДЫДУЩЕГО документа = граница |
| строка «Приложение: … на N л.» | конец предыдущего документа |

⛔ **OCR границу не устанавливает.** На повёрнутых и зеркальных страницах распознавание даёт мусор
(§20.96), вывод OSD о повороте — гипотеза с низкой уверенностью (§20.93), а PDF без текстового слоя
не виден вовсе (§20.94). Из распознавания берётся только НОМЕР ЛИСТА, на который надо посмотреть
(§20.97).

⛔ **Гейт перед описью: отрендерить ПЕРВУЮ страницу каждого предполагаемого документа и убедиться
глазами**, что это шапка нового документа, а не продолжение предыдущего. Пока гейт не пройден,
число документов в блоке считается неустановленным и позиция описи по нему не пишется (правило 66).

Признаки склейки, по которым блок берётся под подозрение: в позиции больше листов, чем бывает
у такого документа · подряд идут ответы разных организаций под одним наименованием · внутри
диапазона встречается вторая подпись либо второй угловой штамп · листаж позиции не сходится
со строкой «Приложение: … на N л.».

⚠ Дополняет §11.96.7 (позиция описи — по содержимому листа): там гейт «прочитать первую строку
каждой страницы диапазона», здесь — **чем именно** начало документа отличается от продолжения
и почему на этом шаге нельзя верить распознаванию.

## 20.92. ⛔ ФОТО ТАБЛИЦЫ — ПРОВЕРИТЬ ПРИВЯЗКУ СТРОК ДО ПЕРЕНОСА ДАННЫХ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

⛔ **Гейт: до переноса данных из фото таблицы взять 2–3 КОНТРОЛЬНЫЕ строки из независимого
источника** (реестр призыва, ВУД, паспорт, ранее подписанный документ) и убедиться, что колонки не
смещены. Контрольные строки брать в **начале, середине и конце** таблицы: смещение бывает не по
всей таблице, а с какого-то листа или после объединённой ячейки.

Признаки смещения, видимые без внешнего источника: у первой либо последней строки одна из граф
пуста · число заполненных значений по колонкам разное · подпись/итог не на своей строке.

⚠ Независимого источника нет — данные из фото идут с пометкой «прочтение — сверить с оригиналом»
и в процессуальный документ **не вносятся** (правило 32).

## 20.93. ⛔ ОРИЕНТАЦИЯ ЛИСТОВ ПРИ СБОРКЕ PDF — Tesseract OSD НЕ ИСТОЧНИК ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

Требование владельца «верх листа влево» реализуется одной строкой (`set_rotation`), но **определять
автоматикой, какие листы повёрнуты, нельзя**: на корпусе владельца Tesseract OSD дал ложные
срабатывания — лист с копией паспорта помечен как перевёрнутый **при уверенности 6.0**.

✅ **Рабочий приём:** поворачивать **только те листы, которые уже landscape по геометрии** (ширина
страницы больше высоты), а «перевёрнутые по OSD» не трогать. Лист, читающийся плохо, лечится вторым
проходом `--psm 3` (§20.96) и просмотром рендера зрением, а не разворотом по подсказке OSD.

⛔ Вывод OSD («страница перевёрнута») в опись, в отчёт и в решение о повороте не переносить:
это гипотеза с низкой уверенностью, а разворот верного листа портит готовое приложение.

## 20.94. ⛔ СЛЕПАЯ ЗОНА ПОИСКА ПО КОРПУСУ — PDF БЕЗ ТЕКСТОВОГО СЛОЯ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

На 04.09.2026 в корпусе **198 PDF на 10 849 страниц не имеют текстового слоя** (в их числе сканы
дел на 650 и 272 листа). Полнотекстовый поиск по корпусу их **не видит**, и ни один инструмент об
этом не предупреждает: поиск молча отвечает «не найдено».

⛔ **Отрицательный результат поиска по корпусу НЕ доказывает отсутствия документа.** Формулировка
в ответе — «в текстовом слое корпуса не найдено», а не «такого документа нет». Утверждение об
отсутствии делается только после трёх шагов:

1. **опись дела / описи томов** — там документ есть, даже если файла в корпусе нет (§20.98);
2. **листинг папки дела** на PDF-сканы (имя файла ищется, содержимое — нет);
3. **рендер или OCR** подозреваемых сканов по ключевому слову.

⛔ **Измеряется и лечится инструментом, а не на глаз:** `scripts/pdf_no_text.py` строит отчёт
«PDF без текстового слоя» по корпусу — список файлов с числом страниц и итогом, отсортированный
по объёму:

⚠ Флаг `--ocr` запускает пакетное распознавание (`ocrmypdf`), но **по умолчанию скрипт НЕ
распознаёт**: десять тысяч страниц — это часы работы, и запускает их владелец осознанно.
Перед утверждением «в деле такого нет» достаточно отчётной части: она показывает, есть ли вообще
непросматриваемые сканы в нужной папке.

⚠ То же ограничение действует на любой вывод «в деле такого нет», построенный на поиске: это
свойство индекса, а не дела (правила 30 и 32).

## 20.95. ⛔ ИМЯ ФАЙЛА С НЕВИДИМЫМ СИМВОЛОМ (U+202F И РОДНЯ) — ПУТЬ СТРОКОЙ НЕ ОТКРЫВАЕТСЯ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

⛔ **Вывод «файла нет» по неудачной попытке открыть путь СТРОКОЙ запрещён** (правило 40): пока имя
не получено от файловой системы, «нет файла» — не факт, а свойство набранной строки.

**Порядок — имя брать программно, по префиксу до подозрительного места, и дальше передавать
ПЕРЕМЕННОЙ, а не переклеивать через текст ответа** (копия из ответа теряет символ и ломается
заново):

```python
import glob
cand = glob.glob(r"C:\...\Сканы\Adobe Scan 15*.pdf")   # префикс — до «странного» места
print([(p, p.encode("utf-8")) for p in cand])          # видно байты e2 80 af
```
```powershell
(Get-ChildItem "C:\...\Сканы" -Filter "Adobe Scan 15*.pdf").FullName
```

**Та же грабля, другие символы:** PUA-символы macOS в именах (памятка раскладки входящих), NBSP
`U+00A0`, `U+200B`, двойной пробел, хвостовой пробел перед расширением. Признак один: **листинг
файл показывает, открытие по строке падает.** Диагностика — `name.encode("utf-8")` и посмотреть
байты, а не переписывать путь ещё раз.

## 20.96. ⛔ ПОВЁРНУТАЯ СТРАНИЦА СКАНА — ВТОРОЙ ПРОХОД `--psm 3` ДО ЛЮБОГО ВЫВОДА ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

⛔ **Гейт: страница, на которой первый проход дал МЕНЬШЕ ~200 кириллических букв, уходит на второй
проход `--psm 3` в обязательном порядке.** Вывод «на странице ничего нет / брак скана / лист
пустой» делается ТОЛЬКО после второго прохода **и** просмотра рендера этой страницы зрением.

```python
import re
def slabo(txt):                       # мало осмысленного → второй проход --psm 3
    return len(re.findall(r"[А-Яа-яЁё]", txt)) < 200
```

⚠ Считать именно кириллические буквы, а не длину строки: мусорный вывод OCR по объёму не отличим
от нормального текста.

## 20.97. ДВУХСЛОЙНОЕ ЧТЕНИЕ СКАНА: OCR — ИНДЕКС, ЗРЕНИЕ — СОДЕРЖАНИЕ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

**Два слоя, у каждого своя задача:**

| Слой | Чем | Для чего | ⛔ Чего НЕ делать |
|---|---|---|---|
| 1. Индекс | `ocr_smart.py` / `tesseract` сплошь по всем листам | найти, **на каких листах** лежат нужные документы: «ПОСТАНОВЛЕНИЕ», «ПРОТОКОЛ ДОПРОСА», фамилия, «о приостановлении», дата | не брать из OCR ни одного значения в документ и в опись |
| 2. Содержание | рендер 150–200 dpi + чтение **зрением** по отобранным листам | Ф.И.О., даты, номера, суммы, формулировки, подписи | не «дочитывать» по OCR листы, до которых глазами не дошли |

⛔ **Из слоя 1 в работу уходит только НОМЕР ЛИСТА, на который надо посмотреть.** Фамилия, сумма
или дата, прочитанные OCR, — гипотеза, а не прочтение; в постраничной описи и в карточке дела они
помечаются «прочтение – сверить с оригиналом» либо не пишутся вовсе.

Границы документов внутри скана и таблица «листы скана → документ → дата → лицо» — раздел «После
прочтения» выше; чем отличается начало документа от продолжения — §20.91; дата снимка — §20.98;
число страниц — §20.99.

## 20.98. ⛔ СКАН ТОМА — СНИМОК НА ДАТУ СКАНИРОВАНИЯ, А НЕ АКТУАЛЬНАЯ КОМПЛЕКТАЦИЯ ★

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

**Порядок — три механических шага, ДО того как содержание скана пойдёт в работу:**

1. **Зафиксировать дату скана** и записать её в шапку постраничной описи и в карточку дела. Берётся
   из имени файла (`Сканы\ГГГГ-ММ-ДД_NNN.pdf`) **и** из времени изменения файла; расходятся — брать
   раннюю и пометить «сверить».
2. **Сравнить с датой актуальной описи тома** (§11.99). Опись свежее скана → ⛔ комплектацию и
   номера листов брать **по описи**, а не по скану. Отсутствие документа в скане при этом означает
   «не попал в снимок», а НЕ «не подшит».
3. **Назвать разницу в ответе** одной строкой: «скан от ДД.ММ.ГГГГ, опись от ДД.ММ.ГГГГ, за
   пределами скана л. NNN–NNN» — и запросить досканирование недостающих листов **до** сборки
   приложения, описи, обложки тома и любых ссылок Том/л.д.

⛔ **«Документа нет в скане» доводом и основанием быть не может** (правило 32: провенанс).
Отсутствие в снимке — свойство снимка, а не дела. Утверждение «в деле такого документа нет»
делается только по актуальной описи либо по слову владельца.

⚠ Число страниц файла ≠ число листов тома: страницы считает PyMuPDF (§20.99), листы дела — опись.

## 20.99. ⛔ ЧИСЛО СТРАНИЦ PDF — ТОЛЬКО ИЗ PyMuPDF

> ⓘ Не жанр — техника приёма документов. Карточка жанра не требуется.

Встроенный просмотрщик PDF и подсказка среды **врут про число страниц**, и врут КРАТНО. Ошибка не
безобидная: по числу страниц планируется сверка, считаются листы для описи и обложек томов,
оценивается объём работы и режется PDF на партии рендера.

⛔ **Заявленное число страниц — НЕ источник ни в каком виде:** ни подсказка среды, ни шапка
инструмента чтения, ни «столько же, сколько листов в сопроводе». Единственный источник —
`page_count`, и в ответе число страниц называется **вместе с тем, чем оно получено**.

```python
import fitz                       # PyMuPDF
print(fitz.open(path).page_count)  # единственный источник числа страниц
```

⛔ В Cowork PyMuPDF нет (§2.5 слоя среды) — там число страниц не утверждать, а сказать, что оно не
проверено. ⚠ Число листов ДЕЛА (для описи и обложки) — это не число страниц файла: считается по
подшитым листам, сверяется с описью (правило 32, §07.05.7).
