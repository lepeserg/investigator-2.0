## 14.11. ГАРАНТ — ПОДПИСНОЙ КАНАЛ СУДЕБНОЙ ПРАКТИКИ ★★

У владельца есть подписной доступ к системе ГАРАНТ (`internet.garant.ru`, полный комплект).
Это дополнительный подписной канал при фактически доступной учётной записи; официальные публикации судебных актов также допустимы. Историческое описание канала: белый список §14.10 даёт тексты норм, но
практику по статье — нет.

### 14.11.1. Где канал работает, а где его нет

- ✅ **Локальная среда — ТОЛЬКО ВСТРОЕННЫЙ БРАУЗЕР** (сессия заведена владельцем 17.08.2026).
  ⛔⛔ **ГАРАНТ держит вход в ОДНОМ БРАУЗЕРЕ** (подтверждено владельцем 21.08.2026): вход из
  **другого** браузера выбивает текущий. Поэтому **в Chrome под аккаунтом ГАРАНТа не входить** — ни
  ассистенту, ни владельцу, — и коннектором к Chrome для ГАРАНТа **не пользоваться**. Пока второго
  браузера нет, встроенный держит вход сам и повторно логиниться не требуется.
  ✅ **Внутри ОДНОГО браузера параллельная работа РАЗРЕШЕНА:** вкладки делят общую банку кук, и
  ассистент может работать с ГАРАНТом **одновременно с сессией владельца** — проверено 21.08.2026.
  Ограничение по браузерам, а не по числу вкладок или сеансов.
  ⚠ До 21.08.2026 навык называл рабочими **оба** пути — это и было причиной вечных разлогиниваний:
  два канала выбивали друг друга.
- ⛔ **В Cowork канала НЕТ** — там песочница без браузера владельца. Фолбэк: белый список §14.10
  (pravo.gov.ru приоритетно) и прямой вопрос владельцу.
- ⛔ **Вход выполняет ТОЛЬКО владелец.** Логин и пароль ассистент не вводит ни при каких условиях,
  даже если они продиктованы. Сессия отвалилась — попросить владельца войти, не пытаться самому.

### 14.11.2. ⛔ Что в поиск НЕ отправляется

Правило — [Шаг 6 основного SKILL.md](../SKILL.md#шаг-6-сверка-права): во внешний поиск передаётся лишь запрос о норме, без материалов дела и персональных данных; см. также [конфиденциальность](20-document-ingestion.md#конфиденциальность).

### 14.11.3. ⚠ Гарант НЕ заменяет официальный источник для ТЕКСТА нормы

Приоритет правила 5 не меняется: текст нормы — pravo.gov.ru и белый список §14.10. Ценность
Гаранта в другом, и она большая:

| Что нужно | Где брать в Гаранте |
|---|---|
| **Практика по конкретной статье** | «**Энциклопедия судебной практики. {название} (Ст. NN УК/УПК)**» — курируемый разбор по пунктам |
| **Позиции высших судов** | «**Позиции высших судов. {название статьи}**» — подборка ВС и КС |
| **Акты судов всех инстанций** | вкладка «**Банк судебной практики**» (практика высших судов есть и в основном комплекте) |
| **Действующая редакция и дата** | карточка документа: строка «**Актуальная ред. ДД.ММ.ГГГГ**» |
| **Актуальность документа** | сервис «**ЧекДок**» |
| **Ведомственные акты** | приказы ГВП, Генпрокуратуры, СК — в базе есть (напр. Приказ СК N 40, Приказ ГВП N 150) |

Фильтры выдачи: «Высшие суды» · «Акты органов власти» · «Комментарии» · «Формы документов».

### 14.11.4. Маршрут поиска

1. **Контекстный поиск** формулой «статья NN {кодекс} {ключевые слова нормы}».
2. Нужен **текст нормы** — открыть первый результат (сам кодекс) и снять строку «Актуальная ред.».
3. Нужна **практика** — открыть «Энциклопедию судебной практики» либо «Позиции высших судов» по
   этой статье; для актов судов — «Банк судебной практики».
4. **Зафиксировать в ответе и в документе:** дату сверки + **редакцию** («ред. УПК от 06.08.2026»)
   + реквизиты источника практики (Пленум, определение КС — дата и номер).

### 14.11.5. ⚠ Технические грабли просмотрщика (набиты 17.08.2026)

- ⛔ **Просмотрщик открывает документ НА НАЙДЕННОМ абзаце, и части статьи ВЫШЕ него в DOM не
  подгружаются.** Нашлась ч. 3, а нужна ч. 1 — прокрутка не помогает; **искать отдельным запросом
  по дословной фразе нужной части**.
- ⛔ **Поиск по заголовку попадает в ОГЛАВЛЕНИЕ**, а не в тело статьи: оглавление содержит названия
  всех статей кодекса.
- ⛔ Поиск подстроки «Статья 186.» поймает «Статья 186.**1**» — брать заголовок целиком
  («Статья 186. Контроль и запись переговоров»).
- ✅ **Самый надёжный приём: искать дословную формулу нужной части** — тогда ответ содержится прямо
  в сниппете выдачи, документ открывать не требуется.
- ✅ **Прямые URL вместо строки поиска (проверено 08.09.2026):** документ по якорю статьи —
  `https://internet.garant.ru/#/document/10108000/entry/290` (УК РФ = `10108000`, номер статьи после
  `entry/`, «291.1» пишется как есть); поиск — `https://internet.garant.ru/#/basesearch/<запрос>/all`.
  Строка поиска ExtJS при этом не трогается — она склеивает новый запрос с прежним значением даже
  после Ctrl+A (воспроизведено 08.09.2026: ушёл запрос «Энциклопедия судебной пЭнциклопедия…»).
  ⚠ Просмотрщик грузит ФРАГМЕНТ документа вокруг якоря: `entry/290` открылся со ст. 285.2, и ст. 285
  в DOM не было — каждую нужную статью открывать своим якорем и строку «Актуальная ред.» снимать заново.
  ⚠ Прямой переход в документ в НОВОЙ вкладке отдал «Ошибка сервиса» (`d.garant.ru`) — работать в той
  вкладке, где выполнен вход: в ней якоря и `basesearch` идут без повторного входа.
  ⚠ **10.09.2026 прямой `entry/`-переход давал «Ошибку сервиса» (`d.garant.ru`) и в той же вкладке** — после
  входа по СМС-коду. Надёжный маршрут к статье кодекса: `basesearch` по заголовку статьи («Статья 31.
  Подсудность уголовных дел УПК») → в выдаче клик по результату «Уголовно-процессуальный кодекс …» (по
  ссылке из `find`, не по координатам: список грузится с задержкой) → фрагмент документа открывается на
  найденной части; статьи ВЫШЕ найденной в DOM нет — искать каждую своим заголовком. Ещё короче — `basesearch`
  по дословной формуле части: текст УПК приходит первым сниппетом, сниппет использовать только как ориентир; полный текст открыть обязательно (историческая запись: так сверялись
  ст. 25 и ч. 3 ст. 317.1).
  ✅ «Энциклопедия судебной практики» по статье ищется `basesearch` по фразе «Энциклопедия судебной
  практики <название статьи>»: сниппет выдачи уже содержит нужный пункт, клик по сниппету открывает
  документ на этом пункте (текст ВЫШЕ пункта в DOM не подгружается — см. первый пункт списка).

### 14.11.6. Чего Гарант не закрывает

⛔ **Акты с грифом ДСП** — прежде всего совместный приказ ГВП и ГВСУ СК России **N 167/67** по
статистическим карточкам. В открытых и подписных базах его нет; коды и формы сверяются **только по
бланкам у владельца** (`references/09-genres-stat-cards.md`).

### ⛔ Проверка живости канала — ПЕРВЫМ действием, до работы над квалификацией

Правило 42 не выполняется оговоркой. Провал 19.08.2026: сессия ГАРАНТа была разлогинена, это
записали строкой «практика окружного суда не сверялась» и **пошли дальше** — правовую ошибку в форме
деяния нашёл потом сам владелец, велев идти в ГАРАНТ.

**Порядок:**

1. **До** сбора аргументации по квалификации — открыть канал и убедиться, что он отвечает и сессия
   жива (любой короткий поиск по признаку состава).
2. Канал мёртв → **остановиться и попросить владельца войти**. ⛔ Учётные данные не вводить никогда.
3. Владелец решил работать без канала → это **его решение**: записать в хэндофф по делу и пометить
   квалификацию как **не подтверждённую практикой** во всех документах, куда она попала.

⚠ В Cowork канала нет вовсе — там пункт 2 сразу переходит в пункт 3.

### ⚠ Грабли строки поиска ГАРАНТа (ExtJS), проверено 19.08.2026

- **Enter поиск не запускает** — нажимать кнопку поиска, иначе кажется, что система «не отвечает».
- **Плейсхолдер строки становится текстом и склеивается с запросом**: первый поиск ушёл как

### ⛔ ПОЧЕМУ ГАРАНТ «ПОСТОЯННО РАЗЛОГИНИВАЕТСЯ» — измерено 21.08.2026

Жалоба владельца: во встроенном браузере приходится входить заново почти каждый раз. **Браузер тут
ни при чём.** ⛔ **Причина — ОДИН активный сеанс на аккаунт:** вход в Chrome выбивал сессию во
встроенном браузере. Подтверждено владельцем 21.08.2026; лечение — не входить в ГАРАНТ из Chrome,
см. §14.11.1. Ниже — измеренная механика сессии, она объясняет вторую половину картины.

**Что измерено на живой сессии:**

| Кука | Срок жизни | Роль |
|---|---|---|
| `garantId` | **год** (до 25.09.2027) | идентификатор устройства |
| `authData`, `session` | **месяц** (до 21.09.2026) | долгая привязка входа |
| `domain_sid` | неделя | вспомогательная |
| ⛔ **`session_id_int_8003`** | **30 минут** | **живая серверная сессия** |

⛔ **Короткая кука — скользящее окно:** замер показал, что срок сдвигается **на каждом запросе**
(до запроса — 12:53, после одного `fetch` — 12:54, то есть снова «сейчас + 30 минут»).
**Простой дольше 30 минут = сессия мертва**, хотя `authData` действует ещё месяц.

**Профиль браузера постоянный, куки НЕ теряются.** Проверено: хранилище —
`%APPDATA%\Claude\Network\Cookies`, файл переписывается в момент захода на сайт; в `Preferences`
нет ни очистки при выходе, ни режима «инкогнито». Закрытие панели браузера сессию не убивает —
после повторного открытия вход сохраняется.

**Практические следствия:**

1. ⛔ **Проверка живости канала (правило 42) сама по себе ПРОДЛЕВАЕТ сессию** — один запрос сдвигает
   окно на 30 минут. Поэтому проверять надо **перед работой над квалификацией**, а не «когда-то в
   начале сессии»: заход в 10:00 не помогает в 12:00.
2. **Долгая работа с перерывами** — держать вкладку ГАРАНТа открытой и раз в ~20 минут делать любой
   запрос. Пока панель браузера открыта, это делает страница:

   ```js
   // вставить в консоль вкладки ГАРАНТа; держит сессию живой, пока вкладка открыта
   setInterval(() => fetch(location.origin + '/', {credentials: 'include', cache: 'no-store'}),
               20 * 60 * 1000);
   ```

3. ⛔⛔ **ГЛАВНОЕ — ОДИН БРАУЗЕР (подтверждено владельцем 21.08.2026).** Вход из **другого**
   браузера выбивает текущий. **В Chrome под аккаунтом ГАРАНТа не входить**; коннектором к Chrome
   для ГАРАНТа не пользоваться. Пока второго браузера нет — встроенный держит сессию, и повторно
   логиниться не нужно.
   ✅ **Внутри одного браузера параллельно работать можно** — вкладки делят банку кук; ассистент и
   владелец пользуются ГАРАНТом одновременно, ничего не выбивая (проверено 21.08.2026).
   ⚠ **Соотношение двух причин:** однократность сеанса — то, что реально заставляло входить заново;
   30-минутное окно само по себе к вводу пароля не приводит (со слов владельца вход восстанавливается
   по `authData`, живущей месяц) — оно лишь означает, что «канал проверен два часа назад» ничего не
   гарантирует.
   ⛔ Вход выполняет только владелец, учётные данные не вводить.
