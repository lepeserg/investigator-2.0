# Личные настройки

Файл `config.example.json` содержит только пустые поля. Скопируйте его в `config.local.json` в корне проекта и заполните свои значения. `config.local.json` исключён из Git; не прикладывайте его вручную к публикации.

| Поле | Содержание |
|---|---|
| `projects_root` | Полный путь к папке результатов вне публичного репозитория; для каждого проекта создаётся отдельная подпапка |
| `templates_root` | Полный путь к локальным бланкам |
| `signer` | ФИО, должность, звание, подразделение и дата начала действия реквизитов |
| `correspondence` | Адрес и способ ответа, телефон, желаемый срок, путь к бланку |
| `tools.extra_path` | Список полных путей к папкам системных программ, которых нет в PATH |
| `tools.tessdata_prefix` | Путь к языковым данным Tesseract, если стандартное обнаружение их не находит |

Пример формата пути на Windows: `"D:/InvestigatorProjects"`. Это учебный путь; папка не создаётся автоматически. В JSON можно использовать прямые слеши.

Пустая строка означает, что значение не задано. `requested_reply_days: null` означает отсутствие пользовательского срока по умолчанию. Профиль не устанавливает законный срок ответа и не подтверждает полномочия подписанта по конкретному делу.

Проверка структуры без вывода персональных значений:

```powershell
py -3.12 local_config.py --check
```

Настройки `tools` читаются запускателем `run.py`. Явно заполненные реквизиты подписанта и контакты преобразуются в локальный `runtime/local-constants.json`, который передаётся совместимым инструментам через `SK_CONSTANTS`. Имена, инициалы, падежные формы и полномочия не выводятся автоматически. Для расширенной прежней схемы можно явно задать `SK_CONSTANTS` на свой JSON вне Git; это значение имеет приоритет. Внешний каталог адресатов для проверки согласованности задаётся через `SK_ADDRESSEES`. Бланк для генератора передаётся явно; заполнение профиля не меняет тексты готовых документов.

Пароли и токены в этот файл не записываются. Условия доступа к моделям принимаются пользователем отдельно. Сведения о конкретном деле и источники полномочий хранятся в рабочем проекте.

Системные программы можно подготовить через `start.cmd`; порядок описан в [установке Windows](WINDOWS-SETUP.md). Пустой `tools.tessdata_prefix` позволяет использовать загруженные установщиком данные из `runtime/tessdata`. Явная настройка профиля имеет приоритет, затем учитывается переменная среды `TESSDATA_PREFIX`, затем данные проекта. Если по явно заданному пути не хватает языков, установщик сообщает об этом и не переписывает этот каталог.
